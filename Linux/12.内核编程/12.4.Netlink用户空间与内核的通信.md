# Netlink 用户空间与内核的通信
之前已经了解到，可以通过字符设备在内核与用户空间的应用程序间传递信息，但是这种信息的传递有一定的局限性（至少以我目前学习的知识看来，字符设备好像无法让内核去向用户空间进行请求）  

Netlink 是一种用于内核和用户空间通信的协议，适用于套接字  

## 内核
### 创建 Netlink 套接字结构
``` C
#include <linux/netlink.h>
struct netlink_kernel_cfg {
    struct module *module;
    int groups;
    void (*input)(struct sk_buff *skb);
    u32 (*filter)(struct sk_buff *skb, struct nlmsghdr *nlh);
    void (*dump)(struct sk_buff *skb);
    int (*done)(struct netlink_callback *cb);
    void (*poison)(struct nlmsghdr *nlh);
    u32 (*get_portid)(struct net *net, struct sock *sk, const struct sk_buff *skb);
};
```

这个结构体决定了 Netlink 如何对消息进行处理，其中的关键成员有：  
* **`struct module *module`**: 指向拥有此 Netlink 套接字的内核模块的指针  
* **`void (*input)(struct sk_buff *skb)`**: 接受到消息时的回调函数  

当拥有这样一个结构体 cfg 之后，就可以创建套接字了：  
``` C
struct sock *netlink_sock = netlink_kernel_create(&init_net, NETLINK_USER, &cfg);
```
关键函数为 **`struct sock *netlink_kernel_create(struct net *net, int unit, struct netlink_kernel_cfg *cfg);`**  

net 参数指示所使用的网络命名空间，通常使用 `&init_net` 即可  
unit 参数是标识符，用于区分相同 Netlink 协议的不同套接字，通常使用 `NETLINK_USERSOCK` 即可  
cfg 参数指向 netlink_kernel_cfg 结构体，决定了套接字的行为  

### Netlink 消息
Netlink 在用户空间和内核之间传递的消息也是以 sk_buff 的结构存在，所以我们收发消息都可以从它里面获取相关的数据以及状态  

对于 `struct netlink_kernel_cfg` 中的 `input`，其传递的参数就是一个 sk_buff，我们可以使用 **`nlmsg_hdr()`** 宏来获取 netlink message header 的指针（主要目的是获取pid）  

其头部格式如下：  
``` C
struct nlmsghdr {
    __u32 nlmsg_len;    /* Length of message including header */
    __u16 nlmsg_type;   /* Message content type */
    __u16 nlmsg_flags;  /* Additional flags for the message */
    __u32 nlmsg_seq;    /* Sequence number for the message */
    __u32 nlmsg_pid;    /* PID of the process sending the message */
};
```

### 构造消息
在发送消息之前，我们也需要构造一个 `struct sk_buff` 来保存数据信息：  
``` C
struct sk_buff *nlmsg_new(size_t size, gfp_t flags);
```
`nlmsg_new()` 将会在消息缓冲区中分配一块区域，其中  
`size` 表示要分配的缓冲区大小（包括消息头和数据）  
`flags` 用于指定内核内存分配的标志，通常是 `GFP_KERNEL` 或 `GFP_ATOMIC`  

之后需要在消息缓冲区中构造消息：  
``` C
struct nlmsghdr *nlmsg_put(struct sk_buff *skb, u32 pid, u32 seq, int type, int payload, int flags);
```
**skb**: 表示用于构造消息的 struct sk_buff 结构体，即 Netlink 消息的缓冲区。  
**pid**: 表示消息的源进程 ID。可置为 0  
**seq**: 表示消息的序列号。可置为 0  
**type**: 表示消息的类型。如 `NLMSG_DONE`  
**payload**: 表示消息的数据部分大小。  
**flags**: 用于设置消息的标志，可置为 0  

这个函数也会返回一个指向 `struct nlmsghdr` 的指针（不知道它和一开始所使用的缓冲区指针是不是同一个），**这个指针通常用于后续的消息数据填充**  

之后就可以用`nlmsg_put()` 返回的指针 nlh，将数据复制到 `nlmsg_data(nlh)` 返回的地址当中（不对，nlmsg_data 返回的好像不是一个地址，应该用 NLMSG_DATA ？）  

### 发送消息（单播）
最后需要设置单播并将其发送出去：  
``` C
NETLINK_CB(skb_out).dst_group = 0;  // unicast， 实测这一步好像可以删除，不知道有什么潜在的影响

int nlmsg_unicast(struct sock *sk, struct sk_buff *skb, u32 portid);
```
其中 sk 表示 Netlink 套接字指针  
skb 是构造的消息体  
portid 即接受消息的进程的 PID  

`nlmsg_unicast()` 返回发送的字节数，当返回负值时表示错误

## 用户空间
### 用户态套接字
用户空间要做的事和普通的网络编程一样，先创建套接字之后绑定相关的信息:  
``` C
int user_sock = socket(AF_NETLINK, SOCK_RAW, NETLINK_USERSOCK);
```

**使用的协议族为 `AF_NETLINK`**   
**对应的地址类型对应的结构体是 `sockaddr_nl`**，可以按以下代码设置:  
``` C
#include <linux/netlink.h>

// 原型：
struct sockaddr_nl {
    sa_family_t nl_family;  /* AF_NETLINK */
    unsigned short nl_pad;  /* Zero */
    __u32 nl_pid;           /* Port ID */
    __u32 nl_groups;        /* Multicast groups mask */
};

struct sockaddr_nl saddr = {
    .nl_family = AF_NETLINK,
    .nl_pad = 0;
    .nl_pid = getpid();
    .nl_groups = 0;         // 不加入任何组播组
};
```

之后将本地的地址绑定到这个套接字上:  
``` C
#include <sys/socket.h>

// 原型
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);   // 成功时返回 0

bind(user_sock, (struct sockaddr*)&saddr, sizeof(saddr));
```

### 构造并发送数据
在内核中构造数据只需要直接使用内核提供的 `nlmsg_new()` 等接口就可以了，但是在用户态，这却是相对繁琐的一步：  
``` C
// 原型 (NLMSG_ALIGN是用于将数据部分大小对齐到 4 字节的倍数)
#define NLMSG_SPACE(size) (NLMSG_ALIGN(size) + NLMSG_HDRLEN)

// 需要动态分配一个 struct nlmsghdr 并设置其参数
struct nlmsghdr *nlh = (struct nlmsghdr *)malloc(NLMSG_SPACE(256));

memset(nlh, 0, NLMSG_SPACE(256));
nlh->nlmsg_len = NLMSG_SPACE(256);
nlh->nlmsg_pid = getpid();
```

之后需要把要发送的数据添加到报文头指向的内存后面，之后就可以发送了:  
``` C
memcpy(NLMSG_DATA(nlh), user_msg, strlen(umsg));

// 原型
ssize_t sendto(int sockfd, const void *buf, size_t len, int flags, const struct sockaddr *dest_addr, socklen_t addrlen);    // 返回成功发送的字节数

socklen_t len = sizeof(struct sockaddr_nl);
sendto(user_sock, nlh, nlh->nlmsg_len, 0, (struct sockaddr*)&daddr, &len);
```
其中 `daddr` 表示内核地址，关键点在于设置 `nf_family = AF_NETLINK` 和 `nf_pid = 0`（指向内核）  

（其实通过 sendto 可以感觉到 netlink 所用的套接字接近 UDP，是无连接的  

### 接收数据
在内核中接受数据将触发回调函数，而用户空间中的程序需要通过 `recvfrom`：  
``` C
// 原型
ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags, struct sockaddr *src_addr, socklen_t *addrlen);  // 返回成功接受的字节数

recvfrom(user_sock, &user_info, sizeof(user_msg_info, 0, (struct sockaddr*)&daddr), &len);
```

需要注意的是，**这是一个同步操作**  

其次，接受来的数据也会以“Netlink消息头 + 消息体”的格式存储，因此我们可以提前定义一个结构体，用于保存消息：  
``` C
typedef struct _user_msg_info
{
    struct nlmsghdr hdr;
    char  msg[MSG_LEN];
} user_msg_info;
```
